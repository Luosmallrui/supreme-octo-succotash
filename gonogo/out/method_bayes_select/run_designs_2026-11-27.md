# 新实验设计：为闭式贝叶斯选择找到“有信息但有偏”的场景（2026-11-27）

背景见 `method_bayes_select.md`。

闭式后验在现有数据上已经做到两点：
- 把轮换设计救回来，比朴素求和高 10–15 个百分点；
- 准确率不低于最好的基线。

但它没有明显超过最好的基线。原因是信息瓶颈：Qwen 不推理时，在已知答案计数之后几乎不提供额外信息（首位每次调用 ≤0.1 nats）；推理时又已经很准。

下面三个实验分别从三个方向提供“有信息但有偏”的选择：
1. 换一个有信息、有偏差的评审（H1）；
2. 换一种让 Qwen 更容易比较内容的提问方式（G2）；
3. 用机制结论改造位置偏差本身（G1）。

## 预先登记的判定标准（看数据之前固定）

- **主指标：** 闭式融合后验的准确率，与多数投票和最好的基线比较。合并所有组，差值按原题整群重采样 5000 次，参数用 5 折交叉拟合，与 `bayes_select.py` 相同。
- **成功：** 至少在一种设置（评审 × 调用预算）下，融合后验比最好的基线高 ≥3 个百分点，且 95% 区间不含 0。
- **失败也要报告：** 如果三个实验都不满足，就把方法写成“统一框架 + 轮换救回”，不声称准确率提升。
- **事先固定的变体：** 线性计数先验，β 按 4 个槽位区间（首位、第 2 位、中间、末位）。层级先验、单一 β 只作消融。

## 计算依据（来自 E1 现有数据，Qwen 分词）

| N | 集合数 | 每次调用平均输入 token | 3 个随机顺序 + 多数答案在前 | N 个循环移位 |
|---|---:|---:|---:|---:|
| 4 | 133 | 5,983 | 3.19M | 3.18M |
| 8 | 130 | 10,693 | 5.56M | 11.12M |
| 16 | 100 | 16,307 | 6.52M | 26.09M |
| 32 | 80 | 19,497 | 6.24M | 24.94M |

每个集合平均有 2.6–3.5 个不同答案。对全部 443 个集合，所有有序答案对一共 3,962 个。

## H1（托管模型，不用 GPU）：DeepSeek-Flash 在 E1 自然集合上做评审

**为什么选它。** E2 中 DeepSeek-Flash：
- 有信息：准确率 80.2%，Qwen3-8B 为 70.2%；
- 有偏：首位效应 +21.5，编号 1 效应 +21.5 和 +46.7；
- 读出与 Qwen 完全相同：预填后取第一个 token 的 top-20 分布，覆盖 ≥0.999 的概率质量。

这正是闭式解能纠偏、又能利用信息的场景。

**范围。** 只做 N ∈ {4, 8}，共 263 个集合，因为编号是一位数，第一个 token 就能读出完整分布。N ≥ 10 需要先确认 DeepSeek 的分词是否把两位数拆开，再决定是否加第二步读出。每个集合包括：
- 3 个随机顺序和多数答案在前，共 1,052 次调用；
- 全部循环移位，共 1,572 次调用。

合计 2,624 次调用，约 23M 输入 token。

**费用。** 非高峰时段约 ¥23；高峰时段（工作日北京时间 9–12 点、14–18 点）价格翻倍。DeepSeek 余额约 ¥3.4，需要充值约 ¥30。

**命令。** 用现有 runner，不需要新代码。在快照 `gonogo/` 下运行；第二条命令接着同一个文件续跑：
```bash
python api_select.py --exp e1 --model deepseek-flash --mode direct --prefill --base-url https://api.deepseek.com --key-file ../deepseek.txt --top-logprobs 20 --max-tokens-param max_tokens --orders r,maj --filter "s['N']<=8" --concurrency 16 --max-in-m 12 --max-out-m 0.1
python api_select.py --exp e1 --model deepseek-flash --mode direct --prefill --base-url https://api.deepseek.com --key-file ../deepseek.txt --top-logprobs 20 --max-tokens-param max_tokens --orders c --filter "s['N']<=8" --concurrency 16 --max-in-m 16 --max-out-m 0.1
```
`bayes_select.py` 需要小改：读取 `out/e1_api-*.jsonl`。

**预测：**
- P1：DeepSeek 单次调用的原始选择在 N=4、8 上不低于多数投票。
- P2：闭式融合（1 次调用、3 个顺序）比多数投票和原始选择都高 ≥3 个百分点。
- P3：在循环移位上，闭式聚合比朴素求和和 3 顺序投票都高。

**可选 H2：** gpt-5.4-mini direct，N ≤ 8，只跑 3 个随机顺序。约 6.6M token，约 $5，剩余 OpenAI 额度（约 $7）够用。读出是 top-5 logprobs 加模型自己写的 `\boxed{}`，所以只作为第二个有编号偏差的评审。

## G2（GPU）：E6 位置平衡的答案对决（direct）

**思路。** 列表式选择里，Qwen 选对 A 只比选错 B 多 11 个百分点；E4 又显示内容比较发生在候选之间的注意力里。把选择拆成两两对决，并且每对都正反各问一次，位置效应就能在设计上精确消去。

**设计。**
- 每个 E1 集合中，每个不同答案取一个代表候选（该答案下编号最小的候选，确定性选取）。
- 对每个有序对 (a, b) 构造 N=2 的提示，模板与 E1 相同（Solution 1 = a，Solution 2 = b），预填读出得到 $p_{ab}=P(\text{选 1})$。
- 两个模型各 3,962 次调用，每次约 2.3K token，共约 9M token。按 E3 v2 direct 的速度（约 3,500 次调用约 20–28 分钟）估计，每个模型约 10–15 分钟。

**闭式解（由目标推出）。**
- 模型：$\mathrm{logit}\,p_{ab}=h+\delta(z_a-z_b)+\varepsilon_{ab}$，其中 h 是首位优势。
- 令 $d_{ab}=\tfrac12[\mathrm{logit}\,p_{ab}-\mathrm{logit}\,p_{ba}]$，h 被精确消去，且 $d_{ab}\sim\mathcal N(\delta(z_a-z_b),\sigma^2)$。
- 在假设 $a^*=a$ 下最大化后验，得到

$$\mathrm{score}(a)=\gamma n_a+\frac{\delta}{\sigma^2}\sum_{b\neq a}d_{ab},\qquad \hat a=\arg\max_a \mathrm{score}(a).$$

- 完全图上的最小二乘排序（Borda 和）因此作为充分统计量自然出现，不是人为指定的。δ、σ 在训练题上用 OLS 闭式估计，γ 同前。

**预测：**
- P4：在对决中，Qwen 对正确答案的平均选择概率（两种顺序平均）明显高于 0.5，区分度高于列表式（A−B 约 +11 个百分点）。
- P5：在 N ≥ 8 上，对决融合比多数投票高 ≥3 个百分点（列表式融合只有约 +1）。
- 额外报告每百万 token 的准确率，与 3 顺序列表式比较成本。

**扩展。** 如果 direct 对决有效，再在 think 模式下对一部分集合做对决，用 Qwen 推荐的采样参数。

## G1（GPU）：E5 牺牲锚点（首位放诱饵，direct）

**思路。** E4 表明首位偏差在编码阶段形成：后面的候选是相对第一个候选来读的，第一个候选成了参照。如果首位放一个已知错误的诱饵，它就会吸收锚定。这时贝叶斯条件化“诱饵错误”的闭式结果很简单：诱饵所在槽位不属于任何答案的 $S(a)$，只进入归一化项。

**设计。**
- 在 E1 的 3 个随机顺序前插入一个诱饵块，作为 “Solution 1”，真实候选的编号顺延为 2..N+1。读出 N+1 个编号上的分布；N ≥ 9 时沿用 E1 的两步读出。
- 两种诱饵：
  - **错误候选：** 同一道题采样到的错误解，优先选答案不在本集合中的；没有就取任一错误解。
  - **空白：** `Solution 1:\n(This solution is intentionally left blank.)`
- 对照：现有 E1 的随机顺序调用（无诱饵）。
- 每个模型 443 个集合 × 3 个顺序 × 2 种诱饵 = 2,658 次调用，约 34M token，约 20–30 分钟。

**预测：**
- P6：诱饵拿到最大的概率份额（像原来的首位一样）。真实候选之间的槽位先验更平：第 2 位与中间的比值，明显小于对照中首位与中间的比值。
- P7：去掉诱饵并重新归一化后，单次调用的准确率高于对照的原始单次调用，融合后验也优于对照的融合后验。
- 证伪：第 2 位继承了首位优势（比值接近对照），说明锚定针对“第一个真实候选”，而不是“第一个块”。

**可选机制版。** 在 E2 布局上做同样处理（944 个布局 × 2 种诱饵），直接比较“A 在第 2 位 vs B 在第 2 位”的效应。

## 建议顺序

1. **H1（DeepSeek）：** 最便宜，只需充值约 ¥30，不占 GPU，不需要新代码；最可能直接满足成功标准。
2. **G2（答案对决）：** GPU 约半小时；闭式解最干净，新颖性潜力最大。
3. **G1（诱饵）：** 由机制结论驱动，风险最高，但无论结果如何都对论文第 6 节有解释价值。

**需要实现的部分：**
- `e5_run.py`（诱饵）、`e6_run.py`（对决），都基于 vLLM、复用 E1 的预填读出；
